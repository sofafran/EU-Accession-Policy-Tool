# Helper tools

These small scripts do the mechanical, repeatable work so that the agent does not do it by hand. They were built and tested at stage 0 of RUN-2026-01 (29 Oct 2026); their versions are recorded in the run record. Each prints its purpose with `--help` and its version with `--version`.

**Set-up:** `pip install -r tools/requirements.txt`, plus the system packages listed at the top of that file (Tesseract with the English, Macedonian and Albanian language data, and Poppler). Shared helpers are in `tools/common.py`.

**Tests:** `python3 tools/tests/test_tools.py --report tools/tests/last_report.csv` runs every tool on small generated samples in a temporary copy of the project; it never touches the real data. Run it after any change to a tool and before each gate, and record the result in the run record.

**Runs and countries (E19):** every tool that takes `--run` defaults to the active run, meaning the latest run folder in `runs/` with a run record (`runs/_template/` is not a run). The run's country is read from the `Target country` field of its run record, written as `Name (CCC)`. The list of country codes and names is in `tools/common.py`. No tool hard-codes a country or run.

To build or change a tool: test it on a small sample and record its version in the run record.

Write them in Python, keep each one short and single-purpose, and give each a `--help` description.

| Tool | What it does | Used in |
|---|---|---|
| `hash_file.py` | Computes the SHA-256 fingerprint of a file. | Stage 2 |
| `acquire.py` | Acquires one source (PC-17, ALN-0008), 1.0.0. It downloads a URL, or with `--manual` copies a file the analyst saved in `sources/_inbox/` (PC-03). It files the original as `sources/<country>/<family>/originals/<source_id>_<label>.<ext>`, makes it read-only, computes its SHA-256 and prints the register fields; `--convert` also writes the text file. It respects robots.txt and stops on a login or paywall page and on HTTP 401, 402, 403, 407, 429 and 451, recording a retrieval failure. It never overwrites an original, does not keep an exact duplicate of a registered file, logs every attempt in `review/<run>/acquisition_log.csv` and never writes to the register. 1.1.0 refuses to file a document whose first pages carry a restricted marking such as LIMITE (LIM-0045). | Stage 2 |
| `near_duplicates.py` | Compares the converted texts of registered sources of one country by overlapping eight-word sequences and lists pairs at or above 0.4 Jaccard or 0.6 containment in `review/<run>/near_duplicates.csv`, marking pairs already recorded with `version_of` (PC-03, PC-17, ALN-0023), 1.0.0. Reads only. Documents written on one template, such as successive payment decisions, can appear as false positives for the reviewer to dismiss. | Stage 2, before G2 |
| `start_extraction.py` | Starts a run's own extraction of a source an earlier run already extracted (evidence schema 1.3, E21): moves the current `extraction` and `classification` records unchanged into `earlier_extractions`, with the earlier run, its country, the source's role and the item IDs it created, and writes a new extraction record for the run. Changes no item. 1.0.0. | Stage 5, before extracting a held source |
| `next_id.py` | Returns the next free ID of a given type by reading the relevant CSV or evidence folder. Never reuses an ID. | All stages |
| `convert_to_text.py` | Converts PDF, HTML, DOCX and XLSX originals to text, writing `=== PAGE n ===` before each page and keeping headings. Uses text recognition for scanned PDFs, in the languages listed in the run record (including Cyrillic scripts where needed), and reports when it did. Version 1.2.0 also reports characters per page and flags thin pages (under 200 characters), noting PDF pages with an image whose text may sit in the image (`--ocr-pages` reruns them, `--density-report` writes a CSV), and warns when more than a quarter of the pages are thin; report thin pages at G2 (PC-17, ALN-0021). | Stage 2 |
| `verify_quotes.py` | Checks that every `stated_text` in an evidence file appears word for word at the cited location of the text file (the page for paged documents, the section for webpages), ignoring only differences in whitespace, line-break hyphenation and Unicode normalisation form (both texts are compared in NFC). It must not treat Latin and Cyrillic letters that look alike as equal. Sets `quote_verified` and writes a report. 1.3.0 (PC-30, ALN-0038): a quote must start and end on a word boundary in the source text; a quote cut mid-word fails with a message saying whether the first or last word is cut. One to three digits running on to the last word are read as a footnote mark ("in place27", "April 20228"), not as a cut. Run over every evidence file on 6 November 2026, three existing quotes fail: MDA-GOV-2025-002-0368, -0409 and -0477 (evidence not edited). | Stages 5, 7, 8 and run 1b |
| `validate_data.py` | Checks evidence files against `schemas/evidence_item.schema.json`, checks CSV headers against the data dictionary, checks that IDs are unique and that every ID referred to exists, checks theme codes against `taxonomy/themes.csv`, and warns if the value, reason or review status of a validated or overridden judgement has changed. Version 1.4.0 also checks that every draft or approved theme issue with in-scope items has at least one recommendation (PC-17, ALN-0020), reads each run's learning log, skips `runs/_template/` and treats a lesson ID reused across runs as an error. 1.5.0 checks earlier extractions (evidence schema 1.3): one record per run, and item lists that name real items held by one run only. 1.6.0 (PC-32, PC-22, PC-26 to PC-28): checks that no row of the registers, judgements, links, entities, taxonomy files or learning logs present at the last commit is missing (by ID, against `git show HEAD:<path>`), and that the decision log keeps its register IDs and change-history entries and is not truncated; skipped with a warning if git is unavailable. A judgement or source quality row with a reviewer and review date must be validated or overridden (error); SQ, LNK and JDG IDs or `X to Y` ranges that a gate log row's `linked_changes` names as validated are checked as warnings, since that column is free text. Judgement values are checked by type, with implementation status `replaced` accepted. Register and requirement countries must be known codes or `multi`; interventions and actors known codes, `EU` or `INT`. The optional columns `run_ids` (requirements), `used_in_runs` (register) and `successor_id` (actors, interventions) are accepted present or absent; their values must name known runs or records, and `used_in_runs` must start with `added_in_run` and match the number of roles (or one role). | Before every gate |
| `export_review.py` | Builds the review spreadsheets for each gate from the CSV and JSON files, so the analyst never reads raw JSON. Version 1.1.0 builds the G0, G1 and G2 packages and the stage 5 hand-coding workbook (`G3-handcoding`), which reads `review/<run_id>/G3_sample.csv` (source_id, pages, reason) and `review/<run_id>/G3_passages.csv` (passage_id, source_id, page, start_text, end_text, why). Sheets for later gates are added and tested before those gates, when there is data to test them on. 1.16.0 adds `G6-refresh` (E18), which writes `G6_refresh.xlsx` for a refresh of a closed run: decisions from `review/<run_id>/G6_refresh_decisions.csv` first, then each proposed judgement that supersedes a validated one (old against new value and reason), the affected issues with what happens to each tier 3 judgement, the links from the refresh items (contradicts and amends first, then items with no link), the new sources and their ratings, candidate new issues, out-of-scope items, new intervention records, the run's refresh limits and the gate rows to confirm; `--sources` names the refresh sources (default: those in `refresh_delta.csv`). Version 1.18.0 (5 November 2026, refresh step 9, E18) adds the `G7-refresh` package (`G7_refresh.xlsx`): decisions from `G7_refresh_decisions.csv` first, then the outputs with their state (rebuilt or kept from G7) and any flag from `review/<run_id>/refresh/output_flags.csv` (flagged first), the proposed implementation statuses beside the previous ones, the proposed evidence confidence and relevance ratings (superseding rows and values below High first) and the earlier rereview flags carried forward. Version 1.19.0 (6 November 2026, RUN-2026-02 stage 11, scaling note S10) scopes the `G6` package to the run: its items (E21), judgements and links only, and dossiers only for the issues the run touches; the dossier year falls back to the register's publication date. 1.19.1 lists in `G1b` only the comparator lines whose notes name the run, when any do. 1.20.0 scopes `G6b` to the run's proposed judgements and comparator gaps, and treats every project country but the run's target as a comparator. 1.21.0 (PC-31): the G5 intervention and actor sheets leave out a country record first found by a later run (an intervention by the run of its first item, an actor by the earliest run whose items name it); G1b uses `run_ids` when filled; the G6-refresh links, source quality ratings and new interventions and the G7-refresh superseded set are scoped to the run. Limitation: an actor added by a later run but named by no item cannot be told apart, as entities have no run column. | Every gate |
| `build_review_page.py` | Regenerates, for the active run (or `--run`), the review page `index.html`, the run's country page `analysis/<country code>.html` and the regional page `analysis.html` (E19), from the run record, gate log, limits log, registers, taxonomy, judgements, outputs and learning log. A closed run also keeps its review page as `review_<run_id>.html`, and a run that is not the active one writes only that file. Writes self-contained files (inline styles and scripts, no external files) that work offline and on GitHub Pages. Assigns each item a status label (`Validated`, `Pending review`, `Proposed`, `Draft`, `Not started`) from the gate log and review status, never from its own judgement. Shows no content that is not in the project files. 1.5.0: labels follow the run (alpha wording only for RUN-2026-01) and the active run links to the review pages kept by earlier runs (E20). 1.6.0: the sources, extraction and classification sections show only the run's own requirement lines, sources and items (E21). 1.6.1: the review page header links to the method explainer `tool-explainer.html` ("How the tool works"). 1.7.0: the country product page and the regional page follow `frontend/FRONT_END_SPEC.md` 0.2 (shared header and design layer in `frontend.py`, issue panel with the analytical chain, evidence drawer, heatmap); the review page is unchanged. 1.8.0 (PC-31): the review and draft country pages show only the run's judgements, links and comparator cases (from its case files or selected at its gates), and the reform issues first drafted in the run or an earlier one; the product page's refresh comparison reads only the run's judgements; implementation status `replaced` has a display label (`frontend.py`, PC-22). The regional page stays shared by design and lists every shared issue. | When a gate package is prepared and after every gate decision |
| `build_outputs.py` | Builds the stage 12 outputs (scope overview, one issue brief per reform issue, coverage and limits report, comparator briefs) in `outputs/<run_id>/` from validated judgements, evidence, entities and links. Narrative sections come from `review/<run_id>/stage12/narrative/`, labelled agent synthesis; evidence item IDs cited anywhere are replaced by numbered references to an annex that quotes each item word for word. `--factpacks` writes the per-issue inputs for those narratives. Added at stage 12 of RUN-2026-01 (1.0.0). Version 1.1.0 reads the country, time window, freeze date and gate IDs from the run's records. Tests (PC-17) rebuild the RUN-2026-01 briefs byte for byte from a copy of the data, check that item IDs stay in the annex with word-for-word quotes, that the status reads Draft before G7, and that one fact pack is written per approved issue. Version 1.3.0 (5 November 2026, refresh step 9, E18): `--issues` (with or without `--coverage`) rebuilds only the named issue briefs and the coverage report, leaving the other outputs as signed off; a validated judgement superseded by a later validated row is not used; tier 2 ratings still proposed are shown marked "(proposed)"; an output that uses evidence or judgements added after the last G7 pass reads as a draft for the next G7; in a full rebuild, shared issues added by a later run with no evidence in this run get no brief. The byte-for-byte test now compares the committed outputs as they stand (41 refresh briefs and the rest from G7), skips files still signed off at G7 that a rebuild would mark as rebuilt, and checks that each of those is flagged in `review/RUN-2026-01/refresh/output_flags.csv`. 1.3.1 (6 November 2026, S10) uses only the run's own judgements and links, so another run's comparator links on shared entities (for example a Moldova comparator link from a North Macedonia intervention) stay out of the run's outputs. 1.3.2 also lists, with the role from the run's own extraction record, sources registered by another run but extracted by this one (held comparator sources, horizontal enlargement passages filed under another country). 1.3.3 lets comparator briefs number and annex every run's items, because reused comparator cases cite another run's evidence (E19); issue briefs still use the run's own items only. 1.4.0 (PC-31, ALN-0041): a shared issue first drafted by another run with no evidence in this run is left out of the run's outputs, fact packs and product page (it appeared as an empty row in the closed North Macedonia scope overview and on its country page); source quality is this run's rating, else an earlier run's, never a later run's; and an issue brief whose shared taxonomy row changed after the taxonomy version recorded on the run's judgements carries a taxonomy note (the tool also prints the list). Rebuilt on 6 November 2026, North Macedonia's scope overview loses five empty rows (RI-FMW-015, RI-FMW-016, RI-TEC-038, RI-TEC-039, RI-TEC-040) and the RI-TEC-028 brief gains the note; the committed outputs were not rewritten. | Stage 12 |
| `product_page.py` | Module used by `build_review_page.py` once a run's outputs have passed G7: renders the country page `analysis/<country code>.html` as a navigable product page (sticky navigation, overview, issue cards with a one-line assessment, filters (area, priority, direction, gap, judgement status, 2026 update), a 2025 to 2026 comparison on every card (E18), search and shareable anchors, High-priority issues, comparators, draft options as internal drafts, evidence and limits) from validated records only, with inline CSS and JavaScript. Country and links come from the run record; wording specific to one run is kept in `RUN_TEXT`. Before G7 the draft review aid is shown instead. Checked headlessly with `tools/tests/analysis_page_test.js` (needs jsdom). | After G7 |
| `regional_page.py` | Module used by `build_review_page.py` (E19): renders the regional landing page `analysis.html`, with country selection, headline findings by country, priority reform issues, technology and AI themes, the same issue compared across countries and links into each country page. Countries come from the table in `runs/rollout_plan.md`. A country's judgements appear only after its run has passed G6, and only validated or overridden judgements that no later validated row supersedes; headline text only after G7. Checked headlessly with `tools/tests/regional_page_test.js`. 1.0.0. | After every gate |
| `refresh_delta.py` | Refresh helper (E18): for newly extracted sources, lists each in-scope item with its issue, the earlier items on the same issue and chain link, and the current judgements, in `review/<run>/refresh/refresh_delta.csv`, with blank columns for the agent's proposed link and effect. Reads only; adds no analysis. | Refresh, after classification of the new sources |

Later, if the number of countries makes the pages too heavy: `build_index.py`, which builds a search index or small database from the files for the country and thematic views. It must always be rebuildable from the files and is never the master copy.


**Two-run test fixture (PC-31, 6 November 2026).** `tools/tests/test_tools.py` copies the real data, builds both closed runs' outputs, review and country pages and the alpha's G5, G6 and G6b packages, then adds a later run's records on their shared entities (a Montenegro run using North Macedonia as a comparator: an evidence file with an item on a North Macedonia intervention, register and requirement rows with `used_in_runs`, `run_ids` and country `multi`, a gate log, limit, taxonomy issue, unmatched queue row, intervention, actor and comparator case, a `leads_to` link from the alpha's intervention and a `contradicts` link to an alpha item, and judgements including a `replaced` status and source quality ratings), rebuilds everything and checks it is byte for byte unchanged. The later run has no run record, so the active run and `index.html` stay put; the regional page, shared by design, is checked to gain only the new issue row. `common.py` reads `used_in_runs` and `run_ids` in `register_role` and `run_requirements` when they are filled, and counts a `multi` register row for a later run.

**Run scoping (E21, 3 November 2026).** Several runs now share the registers and some evidence files. `tools/common.py` gives each tool the run's own view: `run_items` and `run_extraction` (evidence), `run_sources` and `register_role` (source register, with the role in that run) and `run_requirements` (requirement lines, identified by the gate that approved them, or by country before approval). `build_outputs.py` 1.2.0 and `export_review.py` 1.14.0 use them, so a closed run's outputs and pages are not changed by a later run's records. `export_review.py` 1.15.0 (5 November 2026, RUN-2026-02 G4): the G4 second-pass sheet counts the later runs' action names (`added`, `added_non_EU`) as well as the alpha's `added_missed`, and the G4 package adds sheets for proposed issues (`G4_proposed_issues.csv`), candidate issues (`stage7/candidate_issues.csv`), rule issues from G3, the earlier unmatched rows and the run's open unmatched queue rows, when those files exist.
